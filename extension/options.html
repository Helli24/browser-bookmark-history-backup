What gets backed up

One .json (complete, easy to diff) and one .html (importable back into the browser).
Bookmarks barely move from one day to the next, so a daily copy is almost always identical to yesterday's. With this on, a new file appears only when you actually added, moved or removed something — the folder becomes a history of changes instead of a pile of duplicates, and the date on the newest file tells you when you last touched your bookmarks.
0 keeps everything. The most recent snapshot is never deleted, whatever you set here — otherwise leaving your bookmarks alone for longer than this window would eventually remove the only backup you have.
One text file per day with the time, title and URL of every visit.
0 keeps everything, which is the default here: every daily log is unique, so deleting one destroys the only record of that day. The browser itself has already forgotten it.
One row per URL with first visit, last visit and visit count. Keeps growing even though the browser discards visit data after about 90 days.

Schedule

Applies to both. How long each kind is kept is set above, next to its switch; the index is never pruned.

Maintenance

Two one-off jobs, pulling from two different places.
Import from the browser's history
The browser keeps roughly 90 days and then throws the rest away. This reads everything it still holds in one pass — a daily log for every day covered, plus those timestamps in the index. Worth running once, now: what is in there today is gone in three months.
Restore from your backup folder
The other direction: reads your own Index\page-index.jsonl and every visits-<year>.jsonl back into the database. For after a reinstall of the browser or the extension — though pointing the extension at a folder that already holds a backup does this on its own.
